# 小小花园「花花涂鸦」V1 实施报告

日期：2026-11-03。已完成本地实现、构建、自动化规则/网络测试和浏览器视觉验收；尚未发布到腾讯云。

## 技术审查与范围

项目为 TypeScript/Vite + Node/Socket.IO；花园使用 DOM 角色和独立 `/garden` namespace，并非 Phaser 战斗场景。复用原有世界坐标、脚底 Y 排序、输入与服务端模拟。没有更改战斗、大厅、花园 30 人上限、牵手/投掷规则或镜头，也没有新增依赖、付费服务或数据库存储。

## Phase A：交互闭环

修改：`FlowerConfig.ts`、`FlowerTool.ts`、`GardenMode.ts`、`garden.css`。

实现：隐藏标准网格，六瓣卡通花、12 色和原生自定义色、范围/占用预览、点击和连续拖画、自己花朵的橡皮擦。Bresenham 补格并按笔画去重；每 200 ms 最多发送两格，预测花朵确认后转正式，拒绝回滚。UI 捕获输入，Esc 优先关色板；失焦、指针取消、断线结束绘制。花朵无碰撞。

验证：浏览器点击空地增加一朵、重复点击不增加；快速拖动生成连续五格；更换蓝色后只影响新花；擦自己成功、擦别人提示拒绝；色板/Esc、范围外红色预览、390×844 窄屏面板通过。自动化检查不同采样密度的插值、越界和过长路径。

风险：当前花园仍以键鼠为目标，没有新增移动端虚拟摇杆或完整触屏社交操作；窄屏布局检查不代表真实手机玩法验收。

## Phase B：姿态与遮挡

修改：`GardenWorld.ts`、`GardenConfig.ts`、`GardenPose.ts`、`GardenMode.ts`、`FlowerTool.ts`。

校准可见角色身高约 110 世界像素，格宽 71.5、花高 55、种植半径 330。花朵按网格行使用 Canvas，与 DOM 角色按脚底 Y 交错排序；没有裁掉角色下半身。加入风摆和近人轻摆，遵守减少动态效果设置。Ctrl 按住蹲下、移动半速、Space 跳跃退出；牵引/举起等冲突状态优先原社交规则。

验证：真实服务器驱动远端角色站立、蹲下截图，密集花丛遮挡腿部，蹲下主要露头；测试半速、跳跃退出、被举起禁蹲、陈旧输入释放。原有花园移动、牵手、机器人、投掷及网络回归测试通过。

风险：角色外形和花丛密度不同，单朵花不保证遮住整个身体。保留原昵称显示规则。

## Phase C：多人权威同步

修改：`FlowerStore.ts`、`installGarden.ts`、`FlowerReplica.ts`、上述客户端模块。

服务器保存格索引、所有者计数和请求去重结果，校验整数坐标/范围/颜色/配额/所有权/速率。个人 200、总预算 1600、单包最多 32 格、令牌桶每秒补充 12（突发容量 12）。`garden:flowers:plant/erase` 请求、`delta/result` 广播与回应、`sync/snapshot` 全量恢复；欢迎包含快照。增量重复忽略、版本缺口重新同步，不部分应用错版数据。

服务端生成房内稳定身份，同标签页 sessionStorage 保存恢复令牌。连接短暂中断后最多保留身份 30 秒；同一令牌不能同时占多个在线席位。其他玩家还在时离开者花朵保留，恢复身份可擦自己的花；最后一人离开清空花朵与身份。不提供永久账号所有权。

验证：8 个真实 Socket.IO 客户端并发；抢同格只有一个成功；外人删除拒绝；晚加入快照、离开保留、令牌恢复、重发幂等、缺口同步、最后离开清理通过。模拟 150 ms 延迟后重发同请求，没有重复花。纯逻辑测试包含非法颜色、畸形坐标、范围、数量及限速。

风险：延迟/丢确认测试是应用层重发模型；没有执行操作系统级真实丢包整形或公网弱网长时间测试。房间空了或 Host 重启作品即消失。

## Phase D：性能与交付

修改：`tests/flowers.ts`、`tests/flowers-network.ts`、`tests/flower-render.html/.ts`、`package.json`、README。

花朵使用最多 64 个同色/DPR 位图缓存，逐行批量 Canvas 绘制，避免每朵独立 DOM/材质。调试模式在 URL 加 `?flowerDebug=1` 显示网格、实例数、revision、待确认队列及帧耗时。

### 实测

| 场景 | 结果 | 边界 |
|---|---|---|
| 正式地图 162 朵渲染夹具 | 帧间隔中位 16.5 ms，花朵绘制 P95 0.40 ms | 当前电脑/IAB，非低端设备 |
| 合成 1600 朵渲染夹具 | 帧间隔中位 16.7 ms，保存采样绘制 P95 3.50 ms；其他采样约 1.7–3.5 ms | 含同格叠加，只测绘制，不代表正式地图容量 |
| 8 位所有者各 200，服务端 1600 朵 | 建立与快照、清理约 2.6–2.9 ms；JSON 快照约 297 KB | 测试扩大边界，生产地图未扩大 |
| 8 个真实网络客户端并发 | 抢格、广播、恢复、清理测试通过 | 局域本机进程，不是 8 台实体设备 |
| 24 朵实际游戏互动 | 正确显示连续粉色笔画和后加蓝花 | 保存工具/站立/蹲下截图 |

**正式地图目前只有 162 个合法格子（18×9）**。200/1600 是安全预算，并不承诺当前小地图能种满。未为了压力测试改变地图或美术尺度。

### 通过的命令

- `npm run test:flowers`
- `npm run test:garden`
- `npm run test:assets`
- `npm run build`（最后的 sessionStorage 身份恢复修改之后再次构建成功）

1600 朵渲染页仅在 Vite 开发服务访问 `/tests/flower-render.html?flowerDebug=1`，不进入生产构建。构建仍有既有 Phaser 大 chunk 警告；本次不迁移引擎。

### 运行与部署

本地更新后必须重启 Node Host，并让所有客户端刷新；只重新构建页面不能更新服务端协议。使用 `npm run build` 然后 `npm run start:lan`。保留原有 `.env` 和周榜配置，不把服务端密钥提交 Git。

本次只更新本机 Host，不发布腾讯云。未来发布需同时上传前端构建及服务端源码并重启常驻 Node；重启会清空花园作品。

### 后续待验收

真实低端 Windows/Android/iOS、不同 DPR 和原生自定义色板、8 台设备持续拖画、公网丢包/高延迟、长时间内存稳定性尚未完成。帧间隔中位不是完整 FPS 分布，也不是 GPU 计时；Canvas 绘制 P95 不含页面全部布局、角色动画和网络开销。正式扩图前应重新测满地图及大快照同步。

## 尺寸调整（2026-11-03）

按试玩反馈将格宽从 71.5 减为 35.75，花高从 55 减为 27.5，茎叶线宽、叶片和近人摆动半径同比缩小。地图边界、角色、种植距离及数量预算保持原值；当前合法格为 629（37×17）。上文 162 格和对应截图/性能记录属于初版基线，缩小后低身遮挡效果也随之减弱。
