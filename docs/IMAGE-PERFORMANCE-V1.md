## 实现

- 六张图移入 src/assets，由 Vite 生成带内容哈希的 URL；统一 AssetManifest。
- 首页只请求 welcome 和设置 SVG。角色卡为程序生成的 SVG，没有需下载的大图缩略图。
- 移除 Phaser 首页创建和道具图集首页下载；加入房间/试炼前才下载、decode 道具图并创建场景/上传纹理。Phaser 和 SVG HUD 复用同一 URL 和已解码图片对象。
- 花园代码与 CSS 使用动态 import，草地在进入花园时准备。结算图仅在结算界面请求。
- 必要阶段用真实资源完成数和场景完成事件反馈，不模拟百分比；图片和场景各有 20 秒超时，失败提供重试/返回。失败缓存被移除，重试会再次请求。
- 玩家在连接/加入多人房间前完成资源准备，因此沿用现有大厅倒计时、重连与同步协议；没有增加全员 readiness 协议，也不改变服务器开局业务规则。
- `?perf=1` 可显示本地 Resource Timing、首页就绪标记、战斗资源准备时间并导出 JSON，不向任何远端上传数据；普通 URL 不显示诊断面板。

## 缓存与腾讯云发布

| 资源 | Cache-Control |
|---|---|
| Vite /assets/ 下带哈希的 JS/CSS/WebP | public, max-age=31536000, immutable |
| HTML 入口 | no-cache |
| 未哈希 SVG 等静态资源 | public, max-age=0, must-revalidate |
| health / 周榜 | no-store |

Node 原生 HTTP 服务添加正确 WebP MIME、Content-Length、ETag、Last-Modified、HEAD 和 If-None-Match/304。Nginx 反代透传响应头，未设置 proxy_cache；Socket.IO 保持 WebSocket Upgrade 和实时传输。Nginx 为 JS/CSS/JSON/SVG 开启 gzip，不重复压缩 WebP。

更新时先上传全部新哈希资源，再切换 HTML；保留上一版资源供已打开的旧标签页使用。不要覆盖旧哈希文件内容，也不要把原图备份目录放在 Web 根目录。发布包包含前端 dist、源码和缓存配置；数据库密钥仍从受限系统配置读取，不进入打包文件。服务端代码变更需要重启单实例，先确认没有进行中对局。保留服务器旧静态文件用于兼容不等于新版会下载它们；上述体积是新版构建的图片集合，并非服务器磁盘全部历史文件。

## 边界与后续

- 下载瓶颈：已移除错误预加载，压缩并强缓存；腾讯云 5 Mbps 带宽仍限制首访 JS/图片下载。
- 解码瓶颈：关键图在对局前显式 decode 且复用。解码后的 RGBA 大小未缩小；普通 DOM 插画的内部解码缓存由浏览器管理，不能保证浏览器永不重新解码。
- GPU 纹理上传：移到进入游戏前；准备耗时包含场景/CPU 侧纹理创建，但未用 GPU timer query 单独测 GPU 完成时间，不能宣称 GPU 卡顿已完全消除。
- Phaser JS 仍约 1.48 MB（gzip 约 340 KB），首页仍需下载/解析该库。下一轮可拆出整个战斗运行时动态 import，需单独回归事件绑定和场景生命周期。
- 未进行移动端实机、极弱网、多轮统计和 GPU 专项剖析；当前故障重试/超时有自动化验证，尚未完成浏览器网络拦截下的逐项故障截图验收。
