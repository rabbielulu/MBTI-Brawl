# MBTI 大乱斗 — 随机道具系统 V1.0 执行文档

> 用途：供 Codex 在现有 HTML 多人乱斗项目中实现。以现有代码结构、输入映射、角色技能和网络协议为准；本文件描述目标行为，不假定已有具体类名。

## 1. 目标与范围

- 在多人乱斗地图随机刷新四种道具：小心心、狙击枪、溜冰鞋、护盾。
- 玩家接近自动拾取；随机地形（障碍、泥潭、毒区）保持兼容。
- 服务端权威处理生成、拾取、增益、伤害、淘汰与击杀归属；客户端负责展示和输入。
- 单人练习允许测试道具；小小花园模式禁用战斗道具。
- V1 不做道具背包、手动丢弃、死亡掉落、商店、永久装备。

## 2. 已确认的硬规则

1. **主动武器槽只有一个**：拾取新的主动武器会替换旧武器。V1 唯一主动武器为狙击枪。
2. **增益独立于主动武器**：溜冰鞋和护盾可与狙击枪同时存在，也可彼此共存；各自计时。
3. **同类持续增益不叠加强度**：重复拾取刷新完整时长。
4. **护盾可抵挡一次狙击**：狙击命中护盾时，子弹被抵消，护盾立即破碎，目标不掉血。
5. **死亡不掉落道具**：角色被击杀后直接销毁主动武器、清空全部增益，不在地图生成掉落物；玩家退出时同样清空。
6. 地面道具自动拾取；未拾取的道具到期消失；满血无法拾取小心心。
7. 狙击枪临时占用普通攻击输入，角色原有技能键仍可使用；射击或到期后恢复普通攻击。

## 3. 道具配置表（V1 初始测试值，可配置）

| ID | 中文名 | 类型 | 效果 | 持续/持有时间 | 掉落权重 |
|---|---|---|---|---|---|
| `heart` | 小心心 | 即时恢复 | 恢复最大生命值 30%，不超过上限 | 立即生效 | 35 |
| `sniper` | 狙击枪 | 主动武器 | 1 发子弹，命中无护盾玩家即淘汰 | 最多持有 10 秒 | 10 |
| `skates` | 溜冰鞋 | 持续增益 | 移速倍率 ×1.40 | 8 秒 | 30 |
| `shield` | 护盾 | 持续增益 | 普通伤害免疫；挡住狙击则立刻破碎 | 5 秒 | 25 |

- 狙击枪射击前蓄力 0.3 秒；瞄准线对所有玩家可见，命中沿射线的第一个有效目标；实体障碍阻挡射线。
- 小心心只对未满血玩家有效，不消耗道具于满血玩家。
- 所有配置值集中维护，禁止散落在不同客户端与服务端模块中。

## 4. 随机刷新调度

| 开局玩家规模 | 场上道具上限 | 每轮掉落数量 | 随机间隔 |
|---|---:|---:|---|
| 1–2 人 | 2 | 1 | 15–20 秒 |
| 3–8 人 | 4 | 1–2 | 12–18 秒 |
| 9–16 人 | 6 | 2–3 | 10–15 秒 |

- 开局 5 秒后第一次刷新；按开局人数固定档位，不因中途退出而来回切换。
- 每件地面道具存活 15 秒。到达场上数量上限时跳过多余生成，不强行挤入。
- 类型采用配置权重抽样。狙击枪较稀有；出现时可触发全场提示与红色光柱。
- 服务端生成稳定的 `pickupId`、`type`、`position`、`spawnAt`、`expireAt`；所有客户端一致。
- 生成点必须在可行走地图内，不与障碍重叠，不处于泥潭或毒区，不与现有道具重叠，并与玩家出生点保持配置化安全距离。
- 采用有限次随机采样 + 合法候选点回退；若无合法点，本轮少生成或跳过，不能无限循环。
- 地形可随机缺失某种元素；道具生成算法不能假设三类地形一定存在。

## 5. 拾取与状态逻辑

### 5.1 自动拾取

1. 服务端在游戏更新周期检测存活玩家与地面道具的距离。
2. 距离小于配置的拾取半径且道具未过期，校验玩家和道具状态。
3. 同一 `pickupId` 只能被一个玩家成功领取；并发冲突以服务端确定性顺序处理。
4. 领取成功后原子性移除地面道具、应用效果并广播事件。
5. 对于满血小心心，拾取失败，道具继续留在地面供其他玩家领取。

### 5.2 主动武器

- 玩家状态包含 `activeWeapon`（空或 sniper），含 `ammo=1`、`expiresAt`、射击状态。
- 领取新主动武器时先清除旧武器及其瞄准状态，再装备新武器。
- 狙击枪瞄准线跟随角色朝向；客户端可预测绘制，但服务端负责最终射击判定。
- 触发普通攻击时进入 0.3 秒蓄力；蓄力结束后服务器判定射线，消耗子弹并清空武器。
- 超过 `expiresAt`、死亡、离开房间、回合结束均清空武器。
- 射击判定期间须防重复输入、重复消费子弹及重复击杀。

### 5.3 持续增益

- `skates` 与 `shield` 分别存储 `expiresAt`，以服务端时间为准。
- 重复拾取同种增益时，将到期时间设置为 `serverNow + duration`；不累计时长、不叠加强度。
- 溜冰鞋只改变移动速度，不修改攻击、技能冷却或跳跃能力。
- 泥潭减速与溜冰鞋加速按现有移动系统的倍率合成，建议 `finalSpeed = baseSpeed × skillModifiers × terrainModifier × 1.4`，最终由统一移动模块执行并限制合理速度上下界。
- 护盾在有效期内免疫普通攻击及毒区的生命伤害；泥潭减速仍生效。护盾超时消失。
- 如果命中来源为狙击枪且目标护盾有效：取消本次伤害、立即移除护盾、广播破盾事件；不产生击杀。

## 6. 伤害、技能和地形兼容

建议统一伤害处理入口：

1. 验证攻击来源、目标是否有效、目标是否存活。
2. 处理实体障碍及射线阻挡（狙击枪）。
3. 按既有角色技能规则处理无敌、闪避、隐身、反弹等特殊状态；**这些技能与狙击的优先级需根据当前 16 人格实现逐项核对，不能擅自覆盖原技能规则**。
4. 若护盾有效：普通伤害归零；狙击伤害归零并破盾。
5. 若没有有效防护：普通伤害走现有数值流程；狙击命中则直接淘汰。
6. 击杀只记入真正造成淘汰的攻击者，更新击杀榜与存活状态。

狙击只命中射线上的第一个有效玩家；不得穿透障碍或连续击杀多人。毒区是持续环境伤害，不产生玩家击杀归属（除非项目既有规则另有定义）。

## 7. 玩家死亡、退出和比赛结束

- **玩家死亡：清空 `activeWeapon`、`skates`、`shield`，终止瞄准、蓄力及相关特效；不掉落任何道具。**
- 玩家退出：执行同样的状态清理；地面原有道具保持不变。
- 比赛结束/取消：停止调度器，移除全部地面道具和玩家临时状态，避免跨局残留。
- 所有玩家退出时，按现有规则取消比赛，无结果。
- 后续若支持复活，新生命默认不继承上一生命的道具与增益。

## 8. 建议的数据结构（伪代码）

```ts
type PickupType = 'heart' | 'sniper' | 'skates' | 'shield';

type WorldPickup = {
  pickupId: string;
  type: PickupType;
  x: number;
  y: number;
  spawnAt: number;  // authoritative server timestamp
  expireAt: number;
};

type PlayerItemState = {
  activeWeapon: null | {
    type: 'sniper';
    ammo: 1;
    expiresAt: number;
    phase: 'aiming' | 'charging';
    chargeEndAt?: number;
  };
  buffs: {
    skatesExpiresAt: number | null;
    shieldExpiresAt: number | null;
  };
};
```

建议事件（命名可与现有网络协议统一）：

| 事件 | 方向 | 内容 |
|---|---|---|
| `pickup_spawned` | 服务端→客户端 | pickupId、类型、坐标、到期时间 |
| `pickup_removed` | 服务端→客户端 | pickupId、原因：picked/expired/round_end |
| `item_acquired` | 服务端→客户端 | playerId、道具类型、状态及到期时间 |
| `item_state_changed` | 服务端→客户端 | 玩家武器与增益快照 |
| `sniper_fire_request` | 客户端→服务端 | 输入序列号、当前瞄准朝向（服务端验证） |
| `sniper_fired` | 服务端→客户端 | shooterId、轨迹、命中目标、结果 |
| `shield_broken` | 服务端→客户端 | targetId、sourceId |

客户端的瞄准朝向不能直接决定命中：应校验与服务端同步的角色朝向、射击时间及允许的转向速度。事件应具备幂等处理，晚到事件不得复活已消失的道具。

## 9. UI、音效与美术表现

- 地面道具：统一浮动、呼吸缩放、轻微阴影；四种道具在较远距离仍能靠轮廓与颜色辨认。
- 小心心：拾取时红心飞向角色、生命条增长。
- 狙击枪：手持夸张枪械、红色瞄准线、剩余持有时间、射击闪光、命中反馈；稀有掉落出现全场提示。
- 溜冰鞋：脚下轮子或鞋子标识、移动拖尾、8 秒倒计时。
- 护盾：角色周围半透明泡泡、5 秒倒计时、受击弹动、被狙击击中时破碎。
- HUD 显示一个主动武器槽及独立增益状态；不为即时恢复道具增加持有槽。
- 所有表现与服务端状态绑定；状态清除时立即停止特效。
- 遵循现有抽象火柴人风格，不引入复杂写实装备模型。

## 11. 验收测试用例

1. 两人同时接触同一心心，只有一人获得恢复；满血玩家不能消耗心心。
2. 拾取溜冰鞋后 8 秒内移速提高 40%，再次拾取仅刷新时间。
3. 溜冰鞋与护盾同时存在，互不影响；狙击枪可同时持有。
4. 狙击枪只能射一发；10 秒到期自动消失；射击后普通攻击恢复。
5. 狙击线穿过障碍时不能击中障碍后玩家。
6. 狙击命中无护盾玩家立即淘汰且只计一次击杀。
7. 狙击命中有护盾玩家：无伤害、无击杀、护盾立即破碎。
8. 普通攻击和毒区伤害被护盾免疫；泥潭减速仍生效。
9. 玩家死亡时清除武器及全部增益，**不生成掉落物**。
10. 玩家退出、全员退出取消比赛、回合结束后均无状态残留。
11. 道具不生成于障碍、泥潭、毒区或不可达位置。
12. 多人客户端看到一致的道具 ID、拾取结果、护盾状态和淘汰结果。
13. 场上数量达到上限时不超量生成；过期道具自动消失。
14. 断线或延迟情况下不重复拾取、不重复开枪、不重复记击杀。
15. 小小花园不生成战斗道具；单人练习可以测试四种道具。

## 12. Codex 执行指令

1. 先检查现有项目：房间状态、服务器 tick、地形碰撞、玩家血量、角色朝向、攻击输入、技能系统、伤害处理、死亡和击杀榜、事件广播。
2. 输出简短改动计划与将修改的文件列表，再开始实现；复用现有模块和命名，不平行创建第二套伤害/移动系统。
3. 优先完成 P0；P1/P2 可后续迭代。新增参数集中配置。
4. 对尚未定义的技能优先级或输入冲突列出待确认项，不要静默改变 16 人格现有技能。
5. 完成后运行现有测试/构建，新增关键自动化测试，并说明手工多人联机验收方法。
6. 不修改现有随机地形规则、排名机制、房间流程或小小花园社交逻辑，除非为道具集成所必需。
