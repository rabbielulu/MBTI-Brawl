# MBTI 大乱斗 — 小小花园「花花涂鸦」V1 Codex 执行文档

版本：V1.0 | 日期：2026-11-03 | 状态：可执行设计规格

## 0. Codex 执行原则

本功能添加到现有 HTML/Web 多人游戏的「小小花园」模式。**先检查项目实际技术栈、场景结构、输入映射、角色控制、渲染排序和网络协议**，复用现有模块，不要假设使用 Unity、Three.js 或某个固定框架。不要重写既有战斗/社交系统。先实现可验证的最小闭环，再完善视觉与性能。若项目现有约定与下文命名冲突，遵守现有约定并记录映射。

## 1. 目标与范围

### 体验目标
- 玩家选择一朵卡通花，打开色板自定义花瓣颜色，在草地上种植。
- 通过点击和按住左键拖动，在隐藏标准网格上排列花朵，写字、画画、共同创作。
- 花朵约到角色腰部；玩家进入花丛后下半身被自然遮挡；蹲下后主要露出头部。
- 多人同时种花，所有客户端看到一致的花朵布局。

### V1 不做
- 不添加俯视/绘画镜头；保留现有第三人称视角。
- 不做花朵生长、浇水、采集、经济奖励、持久化数据库、跨房间作品、文字自动生成。
- 不改变原有小小花园移动/轻盈跳跃/叠叠乐/牵手/按 E 挥手规则；本模式仍禁止攻击。

## 2. 可配置参数（初始建议，需按角色实际尺寸调校）

| 参数 | 初始值/规则 | 说明 |
|---|---|---|
| gridCellSize | 0.65 × characterHeight | 以现有角色高度为单位，不直接写死世界米数 |
| flowerHeight | 0.50 × characterHeight | 从地面到花朵顶部；微小随机差异不影响遮挡预期 |
| flowerVisualWidth | 0.85–1.0 × gridCellSize | 相邻花冠能形成连续色块 |
| plantingRange | 3 × characterHeight | 鼠标可种植的最大地面距离，防止远程涂鸦 |
| initialPlayerFlowerLimit | 200 | 每位玩家的房间内上限；可配置 |
| initialRoomFlowerLimit | 1600 | 8人房间初始预算，依性能测试调整 |
| plantRateLimit | 12 cells/s | 连续拖动的服务端接受速率上限；超限反馈 |
| crouchSpeedMultiplier | 0.5 | 相对正常移动速度 |
| flowerSwayRadius | 1 × gridCellSize | 玩家经过时附近花朵轻微摆动 |
| palette | 12种预设色 + 自定义色板 | 颜色存为规范化 RGB HEX |

**重要：** 上述均为调参初值，不是已经验证的产品数值。网格尺寸要在游戏内以角色身高、镜头角度和写字可读性联合测试。

## 3. 花朵美术与渲染

- V1 仅一种基础花型：5–6瓣扁平卡通花、黄色花心、绿色茎叶，适配现有极简卡通风格；花瓣颜色由玩家选择。
- 轻微风摆和角色经过时的局部摆动，不能造成大幅跳动或影响图案识别。
- 花朵无实体阻挡碰撞；玩家可以自由穿行。
- 优先使用低开销的实例化/批量渲染；颜色通过实例参数/顶点色/材质参数传递，避免每朵生成独立昂贵材质。
- **遮挡要求：** 花朵按场景真实深度/正确绘制排序覆盖角色身体，不要直接裁掉角色下半身。若当前为 2.5D 或自定义 Canvas 渲染，按世界坐标深度/脚底 Y 排序设计可行的前后遮挡方案。
- 为避免稀疏花朵无法遮挡身体，花丛应由足够宽的花冠、叶片与茎叶构成；单朵花不保证完全隐藏角色。
- 如现有渲染不支持正确交错遮挡，先做一个独立技术验证场景，再全面铺开。

## 4. 网格与种植区域

- 地面使用**逻辑标准网格**，常态不显示。
- 种植模式下，仅在鼠标指向附近显示淡色目标格和半透明花朵预览；不要求显示全地图棋盘。
- 根据场景地面投射射线/拾取点，转换到网格整数坐标 `(gx,gz)`；渲染坐标由网格中心反算。
- 每格最多一朵；占用格不可重复种植；不允许种在地图外、非可种植地面、障碍物内部、特殊不可种植区域。
- 网格基准原点和格子大小由房间/地图统一配置，所有客户端必须一致。
- 对边缘、浮点误差、地形高度差做统一处理；以服务端合法性判断为准。
- **避免角色站立处无法种花：** 玩家自身占据的格子允许种植，花朵不影响行走。

## 5. 输入与 UI

### 工具模式
- 小小花园 HUD 增加「花朵工具」入口；进入种植模式后显示：花朵预览、当前颜色、调色板按钮、橡皮擦按钮、退出按钮、个人剩余可种数量。
- 颜色面板：12个预设颜色 + 原生/自定义 RGB 色板；改变颜色只影响之后种下的花，不批量修改旧花。
- 正常模式：保留原有左键牵手判定与其他操作。
- 种植模式：左键用于种花；鼠标按下开始一次绘制，按住移动连续种植，松开结束。此模式不触发牵手。
- 橡皮擦模式：左键点击或拖动删除**自己**种下的花；不允许删除其他玩家的花。
- `Esc` 关闭色板/退出种植工具（优先关闭最上层 UI）；进入 UI 色板时暂停场景点击种植。
- `Ctrl` 蹲下（建议按住蹲下、松开站起；检查项目已有按键冲突）。`Space` 跳跃时解除蹲下；`E` 挥手保持原逻辑。
- 鼠标被 UI 捕获时不能透传到地面种花；焦点丢失/指针取消时结束绘制。

### 第三人称镜头兼容
- 不新增俯视镜头；保留现有镜头距离、跟随和旋转逻辑。
- 如果现有左键用于旋转镜头，则在种植模式中让左键专用于绘画，镜头旋转使用现有其他操作（如右键拖动）或暂时禁用，按项目实际输入结构适配。
- 在镜头看不到地面的区域不允许种植，预览变为无效状态；不自动穿透角色、墙壁或 UI。

## 6. 点击与拖动连续种植算法

1. `pointerdown` 且命中可种植地面：计算当前网格格子，向服务端提交种植请求，并将格子加入本次笔画的本地去重集合。
2. `pointermove` 且仍按住：拾取新的地面点，从上一有效网格点到当前点沿格子路径做插值/网格遍历，避免鼠标快速移动产生断线。
3. 对路径中的格子按顺序去重，跳过已占用、越界、不可种植、超出玩家种植范围的格子。
4. 客户端显示预测花朵（视觉上与确认花朵区分）；收到服务端确认后转为正式花朵；拒绝时撤销预测并给出轻提示。
5. `pointerup`、取消、切换模式、失焦、断线时结束笔画；重新按下开启新笔画。
6. 为防瞬间大量网络包，客户端按固定节奏批量发送格子请求；服务端逐格验证、限速和确认。
7. 不能仅按鼠标事件采样点直接种植，否则不同设备帧率下会出现不一致的间断线。

## 7. 蹲下与花丛遮挡

### 角色状态
- `Standing`：现有站立/移动动作。
- `Crouching`：按住 Ctrl，角色高度降低，移动速度约为正常的 50%，可慢速移动。
- `Jumping`：按 Space 立即退出蹲下并执行原有跳跃；跳跃期间不保持蹲姿。
- 叠叠乐/牵手与蹲下冲突时，优先遵守现有社交交互规则；V1 可在被牵引/叠人状态禁止蹲下，避免姿态与碰撞异常，需在代码中明确条件。

### 视觉验收
- 单朵花高度约到站立角色腰部。
- 角色在密集花丛中站立：下半身被花朵自然遮挡，上半身明显可见。
- 角色在密集花丛中蹲下：身体基本隐藏，头部隐约可见；最终程度由角色蹲姿与花丛密度共同决定。
- 花朵应随角色经过产生局部摆动；不实现敌对隐身、伤害或攻击判定。
- 角色名牌/昵称的可见性沿用现有社交规则，避免因为蹲下导致 UI 错位；若希望捉迷藏更有趣，隐藏昵称应作为独立后续需求，不在本次默认改变。

## 8. 多人数据模型与同步

### 推荐数据结构（字段名可按项目规范调整）

```ts
type FlowerRecord = {
  id: string;               // 服务端唯一 ID
  roomId: string;
  gx: number;
  gz: number;
  flowerType: 'basic';
  colorHex: string;         // 例如 #FF77AA
  ownerPlayerId: string;    // 稳定的房间内玩家 ID
  revision: number;         // 服务端单调递增版本
};

type PlantRequest = {
  requestId: string;        // 幂等去重
  cells: Array<{gx:number; gz:number}>;
  flowerType: 'basic';
  colorHex: string;
};
```

### 权威原则
- **服务端权威**：格子占用、可种植范围、玩家配额、颜色合法性、所有权和冲突判定都由服务端决定。
- `plant`：客户端请求，服务端验证后分配 ID 与 revision，广播 `flower_added`；重复 requestId 不重复种植。
- `erase`：客户端传 flowerId，服务端校验 ownerPlayerId 后删除并广播 `flower_removed`。
- 同格并发种植：服务端先成功处理者占用，另一请求拒绝；所有客户端最终一致。
- 蹲下状态按现有角色状态同步机制传输（状态变化或现有位置快照附带 crouch 标志），远端平滑过渡，不依赖客户端自行猜测。
- 服务器对每次种植检查玩家位置与种植距离，不能只信客户端命中点。

### 进入房间、断线与退出
- 新玩家加入：先取得花朵快照（含 `snapshotRevision`），再应用该版本之后的增量事件；防止快照与广播交错导致漏花或重复。
- 重连：重新获取快照或从可靠 revision 补齐；若增量日志不可用则完整重拉。
- 玩家离开：花朵保留到房间结束，仍归原 ownerPlayerId；如玩家重连身份恢复则仍可删除自己的花。
- 房间销毁：所有花朵数据释放；不写入持久化数据库。
- 如果房间现有自动取消/销毁规则与此冲突，以房间生命周期为准，避免幽灵房间长期占内存。

### 反滥用与性能
- 服务端限制单玩家数量、房间总数、每秒新增数量、单包格子数量（建议最多32格）、坐标范围和颜色格式。
- 限速后客户端明确显示“种植太快/数量已满”，不静默丢失。
- 网络事件尽量批处理，避免拖动一格一包；可视区域裁剪、实例渲染、局部动画更新。
- 200朵/玩家、1600朵/8人房为初始压力测试规模；先实测低端设备与多人同步再提高。

## 10. 验收用例

1. 点击空地：恰好新增1朵花，吸附网格中心；已有花格不重复新增。
2. 拖动快速画直线、折线和字母：格子连续、无明显断点，不能重复刷同格。
3. 调整色板后再种：新花使用新色，旧花不变；非法颜色被服务端拒绝。
4. 切换工具或点击 UI：不会误种花、误触牵手；退出工具后原交互恢复。
5. 站在密集花丛：腰部以下自然遮挡；Ctrl 蹲下：主要露出头部；Space 恢复跳跃。
6. 花朵不阻挡行走、牵手、叠叠乐；没有攻击能力。
7. 两人同时种同格：最终只有1朵，客户端显示一致。
8. 玩家 A 无法删除 B 的花；A 离开后花仍在；房间结束花清空。
9. 新玩家加入和断线重连：花朵数量、坐标、颜色与服务端一致。
10. 达到个人/房间数量限制和限速：明确反馈，不产生不同步。
11. 8人高频种植压力测试：无明显卡顿、内存持续增长或事件堆积；具体 FPS/延迟门槛根据项目当前基线记录后设定。
