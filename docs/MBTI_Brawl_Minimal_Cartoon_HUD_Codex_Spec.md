# MBTI 大乱斗 — 极简卡通 HUD UI 升级执行需求 V1

> 面向 Codex 的实施文档。参考已确认的第 03 套「极简卡通 / Flat Cute」视觉方向，基于当前深紫色主战场进行 HUD 改造。

## 1. 目标与范围

将现有偏系统默认控件感的浅色 HUD 改为统一的极简卡通视觉，保持深色战场、16 人格火柴人、地形与战斗特效不变。本次仅改动 HUD 的视觉、组件样式、排版及必要的自适应，不重做玩法流程。

**必须保留：** 存活人数、总人数、局内计时、玩家状态/头像队列、设置/全屏、返回玩法菜单、更换人格、重置试炼、角色名标签、观战对象切换及键盘快捷键。具体控件以代码中实际存在的功能为准，不得凭视觉稿新增无效按钮。

**不得改动：** 战斗判定、技能逻辑、角色移动、AI、多人同步协议、服务器逻辑、随机地图生成及摄像机参数。

## 2. 视觉规范

### 2.1 风格关键词

Minimal Cartoon UI / Flat Cute / Soft Sticker / Playful Geometry / Clean Readability。

总体应像简洁的卡通游戏贴纸，而非写实材质、玻璃拟态、赛博朋克或复杂涂鸦。保留一点点不规则轮廓的趣味，但组件几何和文字排版应稳定、规整。

### 2.2 推荐设计 Token（可微调）

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--hud-cream` | `#FFF7E9` | 主要面板背景 |
| `--hud-ink` | `#29243F` | 主文字与描边 |
| `--hud-purple` | `#A68BE8` | 选中态、交互按钮 |
| `--hud-lilac` | `#E6DCF8` | 次级按钮背景 |
| `--hud-yellow` | `#FFD76A` | 胜利、重要提示 |
| `--hud-pink` | `#F6A5C7` | 小面积趣味强调 |
| `--hud-muted` | `#77708D` | 辅助信息 |
| `--hud-shadow` | `rgba(18,15,36,.32)` | 轻量投影 |
| `--hud-radius` | `14px` | 常规圆角 |
| `--hud-stroke` | `2px` | 主要轮廓线 |

颜色为初始建议，不强制替换 MBTI 四大人格阵营的既有经典主题色；阵营颜色只用于头像/状态等小面积强调，避免与战场技能特效竞争。

### 2.3 组件绘制规则

- 主面板：奶油白底、2px 深紫描边、轻微偏移阴影，避免大面积纯白和高强度光晕。
- 按钮：柔和圆角、简洁实心图标；Hover 轻微上浮，Pressed 轻微下压，Disabled 明显降对比。
- 头像：统一外框与间距；存活、死亡、当前选中、观战目标状态有清晰区别，不能只靠颜色区分。
- 文字：优先系统可用的清晰中文无衬线字体；数字可使用略圆润、较粗的字重。禁止为追求手写感而降低中文可读性。
- 装饰：仅允许局部小星星、角贴等极少量点缀；常态 HUD 不要持续漂浮粒子或闪烁。
- 图标：尽量使用已有图标或统一 SVG 线宽；不要混用 emoji、不同风格图标和文本符号。

## 3. HUD 区域改造

### A. 左上：存活人数

- 将现有白色方块改为奶油白贴纸式信息块。
- `02` 作为第一视觉层级，`/ 8 存活` 作为第二层级；数字与标签基线清晰。
- 战斗中人数变化可用 150–250ms 的轻微弹性缩放反馈，不能遮挡场景。

### B. 顶部居中：玩家状态队列

- 保留当前头像顺序和实际状态语义。
- 使用统一的圆角头像框；存活头像清晰，死亡头像灰化并增加死亡符号；当前选中头像用紫色外框或底托突出。
- 8 人时完整显示；未来 16 人时采用压缩间距、滚动或其他可扩展方案，不能简单溢出屏幕。
- 若现有状态是棋子、骷髅、麦克风等图标，保留原有含义，不擅自替换数据模型。

### C. 右上：时间、设置、全屏

- 将计时器改为紧凑的奶油白胶囊或圆角卡片。
- 设置和全屏统一为方形图标按钮，保留 tooltip、键盘和点击行为。
- 与下方操作按钮形成稳定的右对齐布局，不出现重叠。

### D. 右侧：操作按钮组

- `返回玩法菜单`、`更换人格`、`重置试炼` 使用统一的奶油白卡通按钮。
- 左图标右文字，按钮高度、间距、描边和状态一致。
- 依据现有模式决定显示/隐藏，不能将练习模式专属操作强行展示在正式多人对局中。
- 对危险或重置操作保留当前确认逻辑；不新增未经要求的确认弹窗。

### E. 底部居中：观战控制

- 保留当前观战对象名称、剩余人数、左右切换箭头与 A/D 快捷键说明。
- 面板改为奶油白圆角贴纸，紫色左右箭头按钮；中央信息分主次层级。
- 观战面板仅在实际观战状态出现；底部留安全间距，不能遮挡角色核心战斗反馈。

### F. 角色头顶：名字和状态

- 名字标签使用深色场景下清晰可读的浅色文字及轻量描边/阴影。
- 角色名称、MBTI 类型、机器人/玩家标识保持既有信息结构。
- 血条与状态反馈采用更简洁的圆角处理，但不改变其数值映射与显示时机。

## 4. 布局与适配

- 优先适配当前桌面 16:9，检查 1920×1080、1600×900、1366×768。
- 在窄窗口中优先压缩水平间距、折叠低优先级文字，避免把按钮压进战场中央。
- 右上操作组、顶部头像栏、底部观战条之间不得重叠。
- 使用 CSS 变量和可复用组件统一样式，避免逐个硬编码像素位置。
- UI 使用独立层级，保证点击不穿透需要交互的按钮；非交互区域不应阻断游戏指针输入。
- 注意浏览器缩放、Windows DPI 和 Electron 封装时的显示一致性。

## 5. 动效规范

| 状态 | 动效 | 时长建议 |
| --- | --- | --- |
| Hover | 上浮 2px / 阴影略增强 | 120–160ms |
| Pressed | 下压 1–2px / 缩放约 0.97 | 80–120ms |
| 头像选中 | 边框/底色平滑过渡 | 150–200ms |
| 人数变化 | 数字轻微弹性强调 | 180–250ms |
| 观战切换 | 内容短距离淡入 | 120–180ms |

尊重 `prefers-reduced-motion`。不添加持续呼吸闪烁、复杂转场或影响操作响应的延迟。

## 6. Codex 执行步骤

1. **审计项目**：确认 HUD 组件、样式文件、状态来源、事件处理、不同模式显示条件；列出拟修改文件。
2. **建立 Token 与基础组件**：按钮、面板、头像框、数字标签、图标按钮；复用现有框架与技术栈。
3. **逐区替换视觉**：按左上人数 → 顶部头像 → 右上操作 → 底部观战 → 角色标签的顺序实施。
4. **校验功能**：逐项检查原有点击、快捷键、模式切换、玩家状态更新及观战切换。
5. **适配与性能检查**：桌面三种分辨率、窗口缩放、多人状态更新、低性能设备。
6. **提交结果**：提供修改文件列表、前后对比截图、已知问题、未改动的核心逻辑说明。

**重要：** 如果实际项目架构与文档假设不同，先汇报差异并选择最小侵入实现。不要为了 HUD 换框架或重构整个渲染层。

## 7. 验收标准

- [ ] 整体 HUD 与深紫色战场形成统一的极简卡通风格。
- [ ] 不再出现未统一样式的默认白色矩形按钮。
- [ ] 存活人数、计时、玩家状态、观战目标一眼可辨。
- [ ] 所有现有按钮和快捷键功能保持正常。
- [ ] 不同游戏模式的控件显隐正确。
- [ ] 8 人状态栏完整；16 人扩展不会发生明显溢出。
- [ ] 1366×768 及以上桌面分辨率无严重遮挡、重叠或裁切。
- [ ] 角色与战场主体可读性不下降。
- [ ] 无新增明显帧率下降、输入延迟或多人同步问题。
