# MBTI 大乱斗 — 美术与技能特效升级需求 V1

> 用途：交给 Codex 评估并分阶段实施。目标是保持现有 HTML/JavaScript 游戏架构，在未来 PC / Steam 版本中提升视觉品质。

## 1. 美术目标与参考拆解

参考方向：风格化竞技场、低多边形质感的地面、高饱和卡通魔法特效、鲜明的明暗对比和动态反馈。**不是直接复制参考游戏，也不要求改成 3D 游戏。**

推荐方向：**2D 火柴人角色 + 2.5D 场景表现 + 高质量 2D VFX**。

### 1.1 地面
- 深紫蓝色为主，低对比度几何地砖或不规则分块。
- 地砖之间有细微色差、边缘明暗变化，形成层次但不抢角色注意力。
- 角色、障碍物脚下有柔和接触阴影。
- 技能爆发时，地面出现对应颜色的短暂光晕。
- 地面装饰不影响危险区、泥潭、角色位置与碰撞边界的识别。

### 1.2 技能特效
- 明亮的能量核心、彩色外层、飞散粒子、环形冲击波、拖尾、星形闪光。
- 根据技能节奏分为蓄力、爆发、消散三个阶段。
- 优先用层次与节奏建立打击感，而不是一味堆叠发光。

### 1.3 角色与场景融合
- 接触阴影、技能瞬间照亮角色、受击闪白、残影和拖尾。
- 保留16人格的抽象、鬼马火柴人造型，以夸张动作和个性化特效突出角色差异。

## 2. 技术约束

1. 保留现有16人格角色设计、战斗规则、技能、碰撞、移动、随机地图和多人同步逻辑。
2. 不迁移到 Unity；优先复用当前 HTML/JavaScript 渲染框架。
3. 首先检查项目的 `package.json`、渲染入口、Canvas/WebGL 使用情况，再判断是否有必要引入 PixiJS、Phaser 或其他渲染能力。
4. 新增视觉层应与战斗逻辑解耦，视觉动画不能改变服务器权威判定。
5. 兼容未来 Electron Windows EXE / Steam 封装，同时尽量保留 Web 版本。
6. 不要未经确认就大规模重构。

## 3. 地面渲染升级

### 视觉需求
- Stylized Arena Floor / Low-poly Inspired Environment。
- 深紫蓝地面、微妙的几何分块、局部明暗层次。
- 接触阴影与技能地面光晕。
- 保持地图障碍物、泥潭、有毒区域的识别优先级。

### 实现要求
- 优先程序化绘制或可重复纹理。
- 避免每块地砖创建独立 DOM 元素。
- 地面视觉与地形碰撞数据分离。
- 与随机地图生成系统兼容。
- 提供颜色、分块密度、边缘对比、阴影强度等可调参数。

## 4. 可复用 VFX 系统

### A. Anticipation — 蓄力
- 小粒子向技能中心聚集。
- 能量光晕逐渐增强。
- 角色轻微压缩、蓄力或前摇动作。

### B. Impact — 爆发
- 高亮核心闪光。
- 快速扩散的环形冲击波。
- 彩色粒子向外喷射。
- 适度屏幕震动与角色受击闪白。
- 视技能类型添加短暂地面光晕、拖尾或残影。

### C. Dissipation — 消散
- 粒子逐渐减速、缩小、淡出。
- 拖尾和地面光晕自然衰减。
- 避免长时间残留遮挡战场信息。

### 技术要求
- 可配置粒子数量、颜色、速度、方向、生命周期、重力、缩放、透明度。
- 支持 Additive Blending（加法混合）；评估 Bloom 后处理的性能和实现成本。
- 使用对象池减少频繁创建销毁。
- 不同人格技能通过数据配置复用基础特效组件。
- 大量技能同时释放时支持粒子预算和降级。

## 5. 角色动作与反馈

| 状态 | 表现要求 |
| --- | --- |
| Idle | 轻微呼吸、身体晃动 |
| Run | 弹性奔跑与身体倾斜 |
| Attack | 前摇、爆发、恢复 |
| Hit | 闪白、挤压变形、轻微顿帧（仅视觉） |
| Knockback | 击退、短暂残影 |
| Death | 夸张倒地或消散 |
| Victory | 个性化庆祝动作、皇冠与撒花 |

动画不应改变碰撞盒、移动速度或服务器权威战斗判定。

## 6. 性能与平台目标

- Windows PC 优先，目标 60 FPS。
- 当前支持 8 人同屏，预留未来 16 人的渲染扩展空间。
- 提供高 / 中 / 低画质档位。
- 粒子系统限制总量，必要时按视觉重要性降级。
- 避免特效影响网络同步、输入响应与战斗可读性。
- Canvas 2D 可以实现基础粒子、拖尾、阴影与冲击波；真正的 Bloom 或复杂 GPU 粒子需评估 WebGL/后处理支持。

## 7. VFX Playground — 第一阶段验证

先制作独立特效实验页面，不直接修改正式战斗场景。

**必须包含：**
- 一块升级后的竞技场地面。
- 一个现有风格的火柴人角色。
- 一次完整的蓄力 → 爆发 → 消散技能演示。
- 地面光晕、粒子、冲击波、受击反馈。

**可实时调节参数：**
- 粒子数量、速度、生命周期。
- 技能颜色、发光强度。
- 冲击波半径与扩散速度。
- 地面颜色、分块密度、阴影强度。
- 屏幕震动幅度。

目标：像简化版 Unity Particle System 一样，能快速迭代特效而无需每次进入正式战斗。

## 8. 分阶段执行计划

1. **架构检查**：识别渲染技术、依赖、现有动画/粒子实现和性能瓶颈。
2. **视觉原型**：在 Playground 实现地面升级和一套完整技能爆炸。
3. **视觉验收**：确认风格、可读性、性能与操作手感。
4. **系统化**：抽象可复用的 VFX 配置、对象池与角色动画接口。
5. **逐步接入**：按人格和技能分批替换，不一次改动全部16个角色。
6. **PC 验证**：在 Electron 环境测试性能、分辨率、全屏和兼容性。

## 9. 给 Codex 的执行指令

请先检查当前项目的 `package.json`、渲染入口、游戏循环、角色绘制、技能特效和多人同步相关代码。不要直接重构整个游戏。

首先输出：
1. 当前渲染技术与主要限制。
2. 地面视觉升级的具体实现方案。
3. VFX 系统架构与可复用组件。
4. 角色动画升级方案。
5. 预计新增/修改的文件清单。
6. 性能风险、兼容性问题与规避方案。

待方案确认后，仅实现 **VFX Playground** 的最小可运行版本：一块升级后的地面、一个火柴人、一套完整技能爆炸和参数控制面板。验证视觉效果后，再逐步接入正式游戏。
